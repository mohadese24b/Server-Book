    Windows Server vs Azure

    دوره جامع Windows Server & Active Directory · نسخه ۲۰۲۲/۲۰۲۵

    ۱. اهداف یادگیری

    در پایان این درس باید بتوانی:

    • تفاوت اصلی Windows Server و Microsoft Azure را توضیح بدهی.
    • بفهمی Server، Virtual Machine و Cloud چه رابطه‌ای با هم دارند.
    • تفاوت On-Premises و Cloud را درک کنی.
    • تشخیص بدهی چه زمانی استفاده از Windows Server منطقی است و چه زمانی Azure مناسب‌تر است.
    • مفهوم Hybrid Environment را بفهمی.

    ۲. معرفی

    قبل از اینکه وارد نصب و مدیریت Windows Server شویم، باید یک سؤال پایه را جواب بدهیم:

    Windows Server کجاست و Azure چیست؟

    این دو رقیب مستقیم هم نیستند.

    • Windows Server یک سیستم‌عامل سروری است.
    • Microsoft Azure یک پلتفرم Cloud است که می‌توانی در آن سرور، شبکه، Storage، Database و سرویس‌های مختلف ایجاد و مدیریت کنی.

    یک تصویر ذهنی ساده:

    Windows Server
│
└── سیستم‌عامل برای اجرای سرویس‌های Server

Azure
│
├── Virtual Machines
├── Storage
├── Networking
├── Databases
├── Identity
└── سرویس‌های Cloud مختلف
    💡 نکته مهم

    می‌توانی Windows Server را داخل Azure هم اجرا کنی.

    پس مقایسه دقیق‌تر این است:

          On-Premises                     Cloud
┌───────────────────┐         ┌───────────────────┐
│ Your Organization │         │      Azure        │
│                   │         │                   │
│ Physical Server   │         │ Virtual Machine   │
│       ↓           │         │       ↓           │
│ Windows Server    │         │ Windows Server    │
└───────────────────┘         └───────────────────┘

    ۳. Windows Server چیست؟

    Windows Server نسخه‌ای از سیستم‌عامل Windows است که برای محیط‌های Server طراحی شده است.

    برخلاف Windows معمولی که بیشتر برای استفاده شخصی یا Client طراحی شده، Windows Server برای ارائه سرویس به تعداد زیادی Client و مدیریت یک شبکه استفاده می‌شود.

    مثلاً یک Windows Server می‌تواند نقش‌های زیر را داشته باشد:

    • DNS Server
    • DHCP Server
    • File Server
    • Web Server
    • Active Directory Domain Services (AD DS)
    • Print Server
    • و سرویس‌های دیگر

    مثلاً در یک شرکت:

    Windows Server
│
┌───────────┼───────────┐
↓           ↓           ↓
DNS        DHCP         AD
│           │           │
└───────────┼───────────┘
            ↓
     Client Computers

    بنابراین Server معمولاً خودش برای Clientها سرویس فراهم می‌کند.

    ۴. Azure چیست؟

    Microsoft Azure یک پلتفرم Cloud Computing است.

    یعنی به‌جای اینکه همه تجهیزات را خودت در شرکت خریداری، نصب و نگهداری کنی، می‌توانی منابع محاسباتی و سرویس‌های مختلف را از زیرساخت Azure استفاده کنی.

    برای مثال می‌توانی در Azure یک Virtual Machine (VM) بسازی. مثلاً:

    Azure
│
└── Virtual Machine
    │
    └── Windows Server
        │
        ├── IIS
        ├── DNS
        └── Application

    در این حالت Windows Server هنوز همان Windows Server است؛ فقط زیرساختی که آن را اجرا می‌کند در Azure قرار دارد.

    ۵. On-Premises چیست؟

    On-Premises یا به اختصار On-Prem یعنی سازمان خودش زیرساخت را در محل خودش داشته باشد و مدیریت کند.

    مثلاً:

    Company
│
├── Physical Server
├── Switch
├── Router
├── Firewall
├── Storage
└── Windows Server

    در این حالت سازمان معمولاً مسئول مواردی مثل:

    • خرید Server
    • نگهداری Hardware
    • برق
    • Cooling
    • شبکه
    • Storage
    • Backup
    • تعمیرات
    • نصب و مدیریت سیستم‌عامل

    است.

    ۶. Cloud چه تفاوتی دارد؟

    در Cloud، بخش بزرگی از زیرساخت فیزیکی توسط Cloud Provider فراهم می‌شود.

    در Azure:

    Microsoft Azure
│
├── Compute
├── Storage
├── Network
└── سایر سرویس‌ها

    تو به‌جای اینکه الزاماً یک Server فیزیکی بخری، می‌توانی منابع موردنیازت را در Azure ایجاد کنی.

    مثلاً:

    Azure
│
└── VM
    │
    ├── CPU
    ├── RAM
    ├── Disk
    └── Windows Server

    ۷. یک تفاوت مهم: خرید Server در مقابل مصرف Resource

    در محیط سنتی ممکن است بگویی: «برای شرکت یک Server می‌خرم.»

    اما در Cloud معمولاً بیشتر با مفهوم Resource کار می‌کنی. مثلاً:

    «یک Virtual Machine با این مقدار CPU، RAM و Storage ایجاد می‌کنم.»

    بنابراین مدل ذهنی:

    On-Premises Azure
    خرید Hardware استفاده از Cloud Resources
    Physical Server Virtual Machine / سرویس Cloud
    مسئولیت بیشتر زیرساخت فیزیکی با سازمان زیرساخت Azure توسط Microsoft ارائه می‌شود
    ظرفیت محدود به تجهیزات خریداری‌شده امکان تغییر منابع Cloud
    معمولاً سرمایه‌گذاری اولیه بیشتر روی Hardware معمولاً پرداخت بر اساس مصرف/مدل سرویس
    💡 نکته

    این جدول یک ساده‌سازی آموزشی است؛ مدل هزینه و مسئولیت دقیق به نوع سرویس Azure بستگی دارد.

    ۸. آیا Azure یعنی دیگر Windows Server لازم نیست؟

    خیر.

    این یکی از مهم‌ترین نکات این درس است.

    Azure خودش یک سیستم‌عامل جایگزین Windows Server نیست.

    مثلاً می‌توانی داشته باشی:

    Azure
│
└── Windows Server VM

    از طرف دیگر می‌توانی از سرویس‌های Azure استفاده کنی که اصلاً لازم نیست خودت یک Windows Server کامل مدیریت کنی.

    پس:

    Azure ≠ Windows Server

    اما:

    Windows Server
      ↓
 می‌تواند روی
      ↓
  Azure VM
      ↓
   اجرا شود

    ۹. Hybrid چیست؟

    در دنیای واقعی، یک سازمان الزاماً مجبور نیست همه‌چیز را یا On-Premises داشته باشد یا Cloud.

    می‌تواند هر دو را ترکیب کند. به این حالت می‌گوییم:

    Hybrid Environment

    مثلاً:

    Organization
│
┌─────────┴─────────┐
│                   │
On-Premises       Azure
│                   │
Windows Server    Azure VM
│                   │
└─────────┬─────────┘
          │
     Network/VPN

    مثلاً ممکن است:

    • Active Directory در محیط On-Premises باشد.
    • بعضی Applicationها در Azure باشند.
    • Backup در Cloud نگهداری شود.
    • بخشی از Serverها در Data Center شرکت باشند.

    این مدل در محیط‌های واقعی بسیار مهم است.

    ۱۰. Shared Responsibility

    در Cloud یک مفهوم مهم وجود دارد:

    Shared Responsibility

    یعنی مسئولیت همه چیز کاملاً بر عهده Cloud Provider نیست.

    برای مثال، Microsoft مسئول بخش‌هایی از زیرساخت Azure است؛ اما بسته به سرویس انتخابی، هنوز ممکن است تو مسئول مواردی مثل:

    • سیستم‌عامل VM
    • تنظیمات شبکه
    • Application
    • حساب‌های کاربری
    • دسترسی‌ها
    • Patchها
    • تنظیمات امنیتی

    باشی.

    هرچه از IaaS به سمت سرویس‌های مدیریت‌شده‌تر برویم، مسئولیت مدیریت زیرساخت برای مشتری کاهش پیدا می‌کند.

    یک مدل ساده:

    IaaS
│
├── Azure: زیرساخت فیزیکی
└── Customer: بخش بیشتری از VM و OS

PaaS
│
└── Azure: مدیریت بخش بیشتری از Platform

SaaS
│
└── Provider: مدیریت تقریباً کل Application
    💡 نکته

    برای این دوره، فعلاً لازم نیست جزئیات عمیق IaaS/PaaS/SaaS را حفظ کنی؛ فقط منطق آن را بدان.

    ۱۱. مثال عملی

    فرض کن یک شرکت ۵۰ کامپیوتر دارد.

    شرکت نیاز دارد:

    • کاربران مدیریت شوند.
    • کامپیوترها عضو Domain شوند.
    • DNS داشته باشد.
    • فایل‌ها به اشتراک گذاشته شوند.

    یک راه این است:

    Office
│
└── Physical Server
    │
    └── Windows Server
        │
        ├── AD DS
        ├── DNS
        └── File Server

    این یک محیط On-Premises است.

    حالا همان شرکت تصمیم می‌گیرد Server را در Azure اجرا کند:

    Azure
│
└── Virtual Machine
    │
    └── Windows Server
        │
        ├── AD DS
        ├── DNS
        └── File Server

    در هر دو حالت، Windows Server وجود دارد.

    تفاوت اصلی در این است که Server و زیرساختش کجا قرار دارند و چه کسی بخش‌های مختلف زیرساخت را مدیریت می‌کند.

    ۱۲. اشتباهات رایج

    اشتباه ۱

    Azure یک نسخه Cloud از Windows Server است.

    ❌ نادرست. Azure یک Cloud Platform است.

    اشتباه ۲

    اگر Azure داشته باشیم، دیگر Windows Server نداریم.

    ❌ نادرست. می‌توانی Windows Server را به‌صورت VM در Azure اجرا کنی.

    اشتباه ۳

    Cloud یعنی هیچ چیزی را مدیریت نمی‌کنیم.

    ❌ نادرست. مقدار مسئولیت به نوع سرویس بستگی دارد.

    اشتباه ۴

    On-Premises یعنی حتماً Server باید فیزیکی باشد.

    نه الزاماً. می‌توانی در محیط On-Premises هم از Virtualization استفاده کنی:

    Physical Server
      ↓
  Hypervisor
      ↓
Windows Server VM

    پس:

    On-Premises ≠ Physical فقط

    ۱۳. Recall کوتاه

    بدون نگاه کردن به متن جواب بده:

    1. Windows Server چیست؟ → سیستم‌عاملی برای ارائه و مدیریت سرویس‌های Server.
    2. Azure چیست؟ → پلتفرم Cloud مایکروسافت.
    3. آیا Windows Server می‌تواند داخل Azure اجرا شود؟ → بله، مثلاً به‌صورت Azure Virtual Machine.
    4. On-Premises یعنی چه؟ → زیرساختی که سازمان در محیط خودش مستقر و مدیریت می‌کند.
    5. Hybrid چیست؟ → ترکیب محیط On-Premises و Cloud.

    ۱۴. نکات مهم

    • Windows Server = Operating System
    • Azure = Cloud Platform
    • Windows Server می‌تواند روی Azure اجرا شود.
    • On-Premises یعنی زیرساخت در محیط سازمان.
    • Cloud یعنی استفاده از منابع و سرویس‌های ارائه‌شده توسط Cloud Provider.
    • Hybrid یعنی ترکیب On-Premises و Cloud.
    • Cloud به معنی «بدون مسئولیت» نیست.
    • مسئولیت‌ها بر اساس نوع سرویس تقسیم می‌شوند.

    ۱۵. جمع‌بندی مفهومی

    کل درس را می‌توانی با این زنجیره به خاطر بسپاری:

    Windows Server
│
│ سیستم‌عامل
↓
Server Services
│
├── AD
├── DNS
├── DHCP
└── File Server


Azure
│
│ پلتفرم Cloud
↓
Cloud Resources
│
└── VM
    │
    └── Windows Server

    پس سؤال اصلی این نیست که:

    «Windows Server یا Azure؟»

    بلکه باید اول تشخیص بدهی:

    سیستم‌عامل/سرویس من چیست و زیرساخت اجرای آن کجاست؟

    این تفکیک ذهنی بعداً در مباحث Virtualization، Active Directory، Networking و Azure خیلی به کارت می‌آید.

    ۱۶. سناریوی ترکیبی

    سناریو

    یک شرکت ۱۰۰ کاربر دارد و می‌خواهد:

    • کاربران Domain داشته باشند.
    • DNS داخلی داشته باشد.
    • File Server داشته باشد.
    • هزینه خرید چندین Physical Server را کاهش دهد.

    مرحله ۱ — انتخاب محل زیرساخت

    شرکت می‌تواند تمام Serverها را On-Premises نگه دارد:

    Physical Server
      ↓
Windows Server

    یا بخشی از زیرساخت را در Azure قرار دهد:

    Azure
  ↓
Virtual Machine
  ↓
Windows Server

    مرحله ۲ — انتخاب سرویس‌ها

    روی Windows Server می‌توان مثلاً:

    AD DS
DNS
File Services

    را پیاده کرد.

    مرحله ۳ — تصمیم Hybrid

    اگر شرکت بخشی از سرویس‌ها را در ساختمان خودش و بخشی را در Azure نگه دارد:

    On-Premises
    │
    │ Network Connection
    │
  Azure

    یک محیط Hybrid ایجاد می‌شود.

    نتیجه

    نکته اصلی سناریو این است:

    Azure محل/پلتفرم اجرای منابع Cloud است؛ Windows Server سیستم‌عاملی است که می‌تواند یکی از این منابع، مثلاً یک VM، باشد.

    ۱۷. Cheat Sheet

    Windows Server   → Server Operating System
Azure            → Cloud Platform
Azure VM         → Virtual Machine running in Azure
On-Premises      → Infrastructure in organization's environment
Cloud            → Provider-hosted resources/services
Hybrid           → On-Premises + Cloud
Windows Server can run on Azure → Yes
Cloud ≠ No responsibility
IaaS             → Customer manages more
PaaS/SaaS        → Provider manages more

    ۱۸. تست پایانی

    🧪 سؤال ۱ — مفهومی

    کدام گزینه تفاوت اصلی Windows Server و Azure را درست بیان می‌کند؟

    • A) هر دو سیستم‌عامل هستند.
    • B) Windows Server یک سیستم‌عامل و Azure یک Cloud Platform است. ✓
    • C) Azure فقط برای اجرای Linux است.
    • D) Windows Server فقط روی Physical Server اجرا می‌شود.

    پاسخ صحیح: B — Windows Server سیستم‌عامل Server است؛ Azure یک پلتفرم Cloud است.

    🧪 سؤال ۲ — عملی

    یک Administrator در Azure یک Virtual Machine با Windows Server ایجاد می‌کند. کدام عبارت درست است؟

    • A) Azure و Windows Server یک چیز هستند.
    • B) Windows Server دیگر سیستم‌عامل محسوب نمی‌شود.
    • C) Azure زیرساخت Cloud را فراهم کرده و Windows Server روی VM اجرا می‌شود. ✓
    • D) Windows Server فقط در On-Premises قابل اجراست.

    پاسخ صحیح: C — Azure محیط Cloud را فراهم می‌کند و Windows Server می‌تواند سیستم‌عامل VM باشد.

    🧪 سؤال ۳ — مفهومی

    کدام مورد نمونه‌ای از Hybrid Environment است؟

    • A) فقط Physical Server در شرکت
    • B) فقط Azure VM
    • C) بخشی از Serverها On-Premises و بخشی در Azure ✓
    • D) فقط لپ‌تاپ‌های کاربران

    پاسخ صحیح: C — Hybrid یعنی استفاده ترکیبی از محیط On-Premises و Cloud.

    🧪 سؤال ۴ — سناریویی

    شرکتی یک Windows Server را روی یک Physical Server در ساختمان خودش اجرا می‌کند. این محیط چگونه توصیف می‌شود؟

    • A) SaaS
    • B) On-Premises ✓
    • C) Azure Cloud
    • D) Public Cloud

    پاسخ صحیح: B — چون زیرساخت Server در محیط خود سازمان قرار دارد.

    🧪 سؤال ۵ — مفهومی

    کدام عبارت درباره Cloud صحیح‌تر است؟

    • A) در Cloud مشتری هیچ مسئولیتی ندارد.
    • B) Cloud همیشه به معنی استفاده از Virtual Machine است.
    • C) میزان مسئولیت Provider و Customer به نوع سرویس بستگی دارد. ✓
    • D) Cloud فقط برای Windows Server استفاده می‌شود.

    پاسخ صحیح: C — مفهوم Shared Responsibility بر همین اساس است.

    🧪 سؤال ۶ — سناریویی / Troubleshooting

    Administrator می‌گوید: «من فکر می‌کردم با خرید Azure دیگر نیازی به Windows Server ندارم، اما برای یک VM در Azure باید یک Operating System انتخاب کنم.»

    کدام توضیح درست است؟

    • A) Azure خودش Windows Server است.
    • B) Azure یک Cloud Platform است و VM می‌تواند Windows Server را به‌عنوان OS اجرا کند. ✓
    • C) Windows Server فقط برای Physical Server است.
    • D) Azure فقط Storage ارائه می‌دهد.

    پاسخ صحیح: B — Azure و Windows Server دو لایه متفاوت هستند: Azure پلتفرم Cloud و Windows Server سیستم‌عامل است.

    🧪 سؤال ۷ — سناریویی

    یک شرکت AD DS و File Server خود را در ساختمان شرکت نگه داشته، اما بعضی Applicationها را به Azure منتقل کرده است. این معماری چه نام دارد؟

    • A) Workgroup
    • B) On-Premises Only
    • C) Hybrid Environment ✓
    • D) Localhost

    پاسخ صحیح: C — چون بخشی از زیرساخت On-Premises و بخشی در Cloud قرار دارد.

    نتیجه‌ای که باید از این درس در ذهنت بماند

    اگر فقط یک تصویر از این درس حفظ کنی، این باشد:

    ┌─────────────────────────┐
│         Azure           │
│    Cloud Platform       │
│                         │
│  ┌─────────────────┐    │
│  │ Windows Server  │    │
│  │      VM         │    │

On-Premises
│

    │
    └── Windows Server
    💡 نکته پایانی

    Azure و Windows Server رقیب مستقیم نیستند؛ یکی پلتفرم Cloud است و دیگری سیستم‌عامل Server که می‌تواند در آن پلتفرم هم اجرا شود.

    دوره جامع Windows Server & Active Directory · نسخه ۲۰۲۲/۲۰۲۵

    ۱. اهداف یادگیری

    در پایان این درس باید بتوانی:

    • مفهوم Microsoft Roadmap را درک کنی.
    • بفهمی نسخه‌های Windows Server چگونه منتشر و پشتیبانی می‌شوند.
    • تفاوت LTSC و مدل‌های انتشار دیگر را در حد موردنیاز دوره تشخیص بدهی.
    • مفهوم Lifecycle / Support را بفهمی.
    • برای انتخاب نسخه Server، به‌جای صرفاً «جدیدترین نسخه»، معیارهای درست را در نظر بگیری.

    ۲. معرفی

    در درس قبل فهمیدیم Windows Server یک سیستم‌عامل Server است.

    اما Windows Server یک محصول ثابت نیست.

    مایکروسافت در طول زمان نسخه‌های مختلف Windows Server را منتشر می‌کند؛ مثلاً:

    Windows Server 2012
        ↓
Windows Server 2012 R2
        ↓
Windows Server 2016
        ↓
Windows Server 2019
        ↓
Windows Server 2022
        ↓
Windows Server 2025

    بنابراین وقتی یک Administrator می‌خواهد Server راه‌اندازی کند، فقط سؤالش این نیست:

    «Windows Server نصب کنم؟»

    بلکه باید بداند:

    کدام نسخه؟ با چه چرخه پشتیبانی؟ و برای چه محیطی؟

    ۳. Microsoft Roadmap یعنی چه؟

    Roadmap یعنی مسیر و برنامه کلی توسعه یک محصول در طول زمان.

    در مورد Windows Server، Roadmap به ما کمک می‌کند بدانیم:

    • چه نسخه‌هایی منتشر شده‌اند.
    • نسخه فعلی چیست.
    • نسخه‌های آینده چه مسیری دارند.
    • هر نسخه چه مدت پشتیبانی می‌شود.
    • چه زمانی باید برای Upgrade یا Migration برنامه‌ریزی کنیم.

    مدل ذهنی:

    Release
   ↓
Deployment
   ↓
Updates
   ↓
Support
   ↓
Upgrade / Migration

    یعنی Lifecycle یک Server با نصب آن تمام نمی‌شود.

    ۴. Windows Server Lifecycle

    یکی از مهم‌ترین مفاهیم این درس:

    Lifecycle

    هر نسخه Windows Server یک دوره پشتیبانی دارد.

    در این دوره، Microsoft برای آن نسخه به‌روزرسانی‌ها و پشتیبانی مربوط به Lifecycle آن را ارائه می‌کند.

    پس Administrator باید بداند Server سازمانش تا چه زمانی در وضعیت پشتیبانی قرار دارد.

    ۵. Mainstream و Extended Support

    در مدل Lifecycle مایکروسافت، به‌طور سنتی دو مرحله مهم وجود داشته است:

    Mainstream Support

    مرحله اصلی پشتیبانی محصول است.

    در این دوره معمولاً مجموعه گسترده‌تری از پشتیبانی و به‌روزرسانی‌ها ارائه می‌شود.

    Extended Support

    بعد از Mainstream Support، محصول وارد Extended Support می‌شود.

    در این مرحله دامنه پشتیبانی محدودتر می‌شود و محصول به پایان عمر خود نزدیک‌تر است.

    مدل ساده:

    Release
   │
   ▼
Mainstream Support
   │
   ▼
Extended Support
   │
   ▼
End of Support
    💡 نکته

    جزئیات دقیق نوع Update و مدت پشتیبانی به محصول و نسخه بستگی دارد؛ بنابراین برای کار واقعی باید Lifecycle همان نسخه را بررسی کرد.

    ۶. چرا Lifecycle مهم است؟

    فرض کن یک شرکت هنوز Server بسیار قدیمی دارد.

    ممکن است Server همچنان روشن باشد و کار کند.

    اما:

    کار کردن Server ≠ پشتیبانی شدن Server

    مثلاً:

    Server روشن است
        ↓
Application کار می‌کند
        ↓
اما نسخه OS به پایان Support نزدیک شده
        ↓
باید برای Upgrade / Migration برنامه‌ریزی شود

    این موضوع از نظر:

    • امنیت
    • دریافت Update
    • سازگاری نرم‌افزارها
    • پشتیبانی فنی
    • برنامه‌ریزی زیرساخت

    اهمیت دارد.

    ۷. Windows Server 2025

    در حال حاضر یکی از نسخه‌های اصلی جدید Windows Server، Windows Server 2025 است.

    اما یک نکته مهم آموزشی:

    «جدیدترین نسخه» الزاماً به معنی «باید فوراً همه Serverها را به آن Upgrade کنیم» نیست.

    Administrator باید مواردی مثل:

    • Compatibility
    • Application Requirements
    • Hardware
    • Driver
    • Licensing
    • Support Lifecycle
    • Migration Path

    را بررسی کند.

    ۸. LTSC چیست؟

    در Windows Server با مفهوم:

    LTSC = Long-Term Servicing Channel

    مواجه می‌شوی.

    هدف LTSC این است که یک نسخه Server برای مدت طولانی‌تری با تمرکز بر ثبات و چرخه سرویس‌دهی بلندمدت مورد استفاده قرار گیرد.

    برای Serverهای سازمانی این موضوع اهمیت زیادی دارد، چون سازمان معمولاً نمی‌خواهد سیستم‌های حیاتی خود را دائماً به نسخه‌های جدید منتقل کند.

    مدل ذهنی:

    Server
  ↓
Stability + Long-term Support
  ↓
LTSC

    ۹. Feature Update در مقابل Server Lifecycle

    یک نکته مهم:

    در سیستم‌های Client ممکن است با مفهوم Feature Updateهای مکرر روبه‌رو شوی.

    اما Windows Server برای محیط‌های سازمانی معمولاً با رویکرد متفاوتی مدیریت می‌شود.

    در محیط Server، مواردی مثل:

    Stability + Support + Compatibility

    اهمیت بسیار زیادی دارند.

    چون یک تغییر کوچک در Server ممکن است روی تعداد زیادی Client یا سرویس تأثیر بگذارد.

    ۱۰. Roadmap فقط درباره Version نیست

    Roadmap را فقط به شکل این فهرست نبین:

    2016 → 2019 → 2022 → 2025

    یک Administrator باید به چرخه کامل نگاه کند:

    Version
   ↓
Support Lifecycle
   ↓
Updates
   ↓
Application Compatibility
   ↓
Upgrade Planning
   ↓
Migration

    مثلاً اگر سازمان Windows Server 2019 دارد، سؤال درست فقط این نیست:

    «نسخه جدیدتر چیست؟»

    بلکه:

    «نسخه فعلی تا چه زمانی پشتیبانی می‌شود و چه زمانی و با چه روشی باید Upgrade یا Migration انجام شود؟»

    ۱۱. Upgrade و Migration

    این دو مفهوم را از همین الان از هم جدا کن.

    Upgrade

    یعنی نسخه سیستم‌عامل موجود را به نسخه جدیدتر منتقل کنیم.

    مثلاً:

    Windows Server 2019
        ↓
Windows Server 2025

    در Upgrade، تلاش می‌شود محیط موجود تا حد ممکن حفظ شود.

    Migration

    یعنی سرویس یا Workload را به محیط یا Server دیگری منتقل کنیم.

    مثلاً:

    Old Server
    │
    │ Migration
    ▼
New Server

    این تفاوت در درس‌های بعدی، مخصوصاً Windows Server Upgrade، خیلی مهم خواهد شد.

    ۱۲. مثال عملی

    فرض کن یک شرکت این وضعیت را دارد:

    Server 1  →  Windows Server 2016
Server 2  →  Windows Server 2019
Server 3  →  Windows Server 2022

    Administrator نباید بدون بررسی همه را به یک نسخه جدید منتقل کند.

    ابتدا باید برای هر Server بررسی کند:

    Current Version
      ↓
Support Status
      ↓
Application Compatibility
      ↓
Hardware Requirements
      ↓
Upgrade/Migration Path
      ↓
Plan

    مثلاً ممکن است برای Server 1:

    Migration به Server جدید

    راه مناسب‌تری باشد تا Upgrade مستقیم.

    ۱۳. اشتباهات رایج

    اشتباه ۱

    Roadmap یعنی فقط فهرست نسخه‌های Windows Server.

    ❌ ناقص است.

    Roadmap شامل مسیر توسعه، انتشار و Lifecycle محصول نیز می‌شود.

    اشتباه ۲

    اگر Server روشن است، پس مشکلی ندارد.

    ❌ نادرست.

    ممکن است سیستم‌عامل هنوز کار کند ولی به پایان Support رسیده باشد.

    اشتباه ۳

    همیشه باید جدیدترین نسخه را نصب کنیم.

    ❌ نادرست.

    باید Compatibility، Support، Application و شرایط سازمان بررسی شود.

    اشتباه ۴

    Upgrade و Migration یکی هستند.

    ❌ نه دقیقاً.

    • Upgrade تغییر نسخه سیستم‌عامل موجود است.
    • Migration انتقال Workload یا سرویس به محیط/Server دیگر است.

    ۱۴. Recall کوتاه

    بدون نگاه کردن جواب بده:

    1. Lifecycle چیست؟ → چرخه عمر و دوره پشتیبانی محصول.
    2. LTSC چیست؟ → Long-Term Servicing Channel؛ مدل سرویس‌دهی بلندمدت برای نسخه‌های مناسب محیط‌های پایدار و سازمانی.
    3. آیا جدیدترین نسخه همیشه بهترین انتخاب فنی است؟ → نه؛ باید Compatibility و Support و نیاز محیط بررسی شود.
    4. Upgrade چیست؟ → ارتقای نسخه موجود.
    5. Migration چیست؟ → انتقال سرویس/Workload به Server یا محیط دیگر.

    ۱۵. نکات مهم

    • Windows Server نسخه‌های مختلف دارد و هر نسخه Lifecycle مشخصی دارد.
    • Lifecycle برای برنامه‌ریزی زیرساخت بسیار مهم است.
    • Mainstream Support و Extended Support مراحل مهم چرخه پشتیبانی هستند.
    • LTSC برای سناریوهای نیازمند چرخه سرویس‌دهی بلندمدت اهمیت دارد.
    • جدیدترین نسخه الزاماً بدون بررسی بهترین گزینه برای یک سازمان نیست.
    • Upgrade ≠ Migration
    • قبل از Upgrade باید Compatibility و Support و Requirements بررسی شود.

    Roadmap را این‌طور در ذهنت نگه دار:

│              │              │

    ۱۷. سناریوی ترکیبی

    وضعیت

    یک شرکت سه Windows Server دارد:

    DC1    →  Windows Server 2016
APP1   →  Windows Server 2019
FILE1  →  Windows Server 2022

    شرکت می‌خواهد زیرساخت خود را به‌روز کند.

    مرحله ۱ — بررسی Version

    ابتدا نسخه فعلی هر Server مشخص می‌شود.

    مرحله ۲ — بررسی Lifecycle

    برای هر نسخه باید وضعیت Support بررسی شود.

    مرحله ۳ — بررسی Application

    مثلاً APP1 ممکن است نرم‌افزاری داشته باشد که با نسخه جدید سازگار نباشد.

    پس نمی‌توان فقط گفت:

    «همه را همین امروز Upgrade کنیم.»

    مرحله ۴ — انتخاب روش

    ممکن است انتخاب شود:

    DC1    →  Upgrade
APP1   →  Migration
FILE1  →  فعلاً بدون تغییر

    این تصمیم صرفاً بر اساس قدیمی یا جدید بودن نیست؛ بلکه بر اساس نیاز و Compatibility محیط است.

    نتیجه

    Roadmap به Administrator کمک می‌کند قبل از رسیدن Server به پایان Support برای آینده آن برنامه‌ریزی کند.

    🧪 سؤال ۱

    هدف اصلی بررسی Lifecycle یک Windows Server چیست؟

    • D) ساخت User

    پاسخ صحیح: B — Lifecycle مشخص می‌کند محصول در چه مرحله‌ای از چرخه عمر و پشتیبانی قرار دارد.

    • A) چون Server کار می‌کند هیچ کاری لازم نیست.

    کدام گزینه تفاوت Upgrade و Migration را بهتر نشان می‌دهد؟

    • B) Upgrade انتقال فایل‌ها و Migration تغییر IP است.
    • C) Upgrade ارتقای نسخه موجود است؛ Migration انتقال سرویس یا Workload است. ✓
    • D) Upgrade فقط برای Client و Migration فقط برای Router است.

    پاسخ صحیح: C

    🧪 سؤال ۵ — سناریویی

    یک شرکت می‌خواهد Windows Serverهای خود را به نسخه جدید منتقل کند. یکی از Serverها Application مهمی دارد که هنوز Compatibility آن بررسی نشده است. بهترین اقدام فنی قبل از تغییر چیست؟

    • A) بلافاصله Upgrade انجام شود.
    • B) Application Compatibility بررسی شود. ✓
    • C) Server حذف شود.
    • D) Userها حذف شوند.

    پاسخ صحیح: B — Compatibility یکی از معیارهای مهم قبل از Upgrade یا Migration است.

    کدام عبارت درباره Roadmap صحیح‌تر است؟

    • A) فقط نام نسخه‌های آینده را نشان می‌دهد.
    • B) فقط برای Clientهاست.
    • C) به برنامه‌ریزی Version، Lifecycle، Support و تغییرات آینده کمک می‌کند. ✓
    • D) جایگزین Active Directory است.

    پاسخ صحیح: C — Roadmap دید بلندمدت‌تری نسبت به Version و Lifecycle می‌دهد.

    🧪 سؤال ۷ — سناریویی

    Administrator می‌گوید: «Windows Server 2025 جدیدترین نسخه است، پس بدون هیچ بررسی باید تمام Serverهای شرکت را به آن Upgrade کنیم.»

    مشکل اصلی این تصمیم چیست؟

    • A) Windows Server 2025 سیستم‌عامل نیست.
    • B) جدیدترین نسخه همیشه نباید بررسی شود.
    • C) قبل از Upgrade باید Compatibility، Requirements و مسیر Upgrade/Migration بررسی شود. ✓
    • D) Windows Server فقط روی Linux اجرا می‌شود.

    پاسخ صحیح: C — در محیط واقعی، تصمیم Upgrade باید بر اساس شرایط Server و Workload گرفته شود، نه صرفاً جدید بودن Version.

    Windows Server Editions & Installation

    دوره جامع Windows Server & Active Directory · نسخه ۲۰۲۲/۲۰۲۵

    ۱. اهداف یادگیری

    در پایان این درس باید بتوانی:

    • تفاوت Windows Server Editions را در حد موردنیاز دوره تشخیص بدهی.
    • تفاوت Standard و Datacenter را بفهمی.
    • مفهوم Server Core و Desktop Experience را در زمان نصب تشخیص بدهی.
    • مراحل اصلی نصب Windows Server را بشناسی.
    • برای یک سناریوی واقعی، Edition و نوع Installation مناسب را انتخاب کنی.

    ۲. معرفی

    تا اینجا فهمیدیم Windows Server یک سیستم‌عامل Server است و نسخه‌های مختلفی دارد.

    اما هنگام نصب با یک انتخاب دیگر هم روبه‌رو می‌شویم:

    کدام Edition را نصب کنیم؟

    برای مثال در Windows Server با Editionهایی مثل:

    • Standard
    • Datacenter

    مواجه می‌شوی.

    و هنگام Installation نیز باید مشخص کنی:

    • Server Core
    • Server with Desktop Experience

    پس نصب Windows Server فقط «Next → Next → Install» نیست.

    مدل ذهنی این درس:

    Windows Server
│
├── Edition
│   ├── Standard
│   └── Datacenter
│
└── Installation Option
    ├── Server Core
    └── Desktop Experience

    ۳. Windows Server Editions

    Standard

    Windows Server Standard برای بسیاری از محیط‌های معمول Server مناسب است.

    مثلاً:

    • File Server
    • DNS Server
    • DHCP Server
    • Application Server
    • Domain Controller

    می‌توانند روی آن اجرا شوند.

    اما قابلیت‌های Virtualization و بعضی قابلیت‌های پیشرفته در Standard محدودتر از Datacenter هستند.

    Datacenter

    Windows Server Datacenter Edition برای محیط‌های بزرگ‌تر و به‌خصوص سناریوهای Virtualization و قابلیت‌های پیشرفته طراحی شده است.

    در Datacenter قابلیت‌های بیشتری در زمینه‌هایی مثل:

    • Virtualization
    • Storage
    • Software-defined Networking
    • قابلیت‌های پیشرفته Data Center

    وجود دارد.

    بنابراین نباید تصور کنی:

    Standard   = Server ضعیف
Datacenter = Server سریع‌تر

    تفاوت اصلی Feature Set و Licensing Rights است، نه اینکه یکی ذاتاً CPU یا RAM بیشتری داشته باشد.

    ۴. Standard vs Datacenter

    یک مقایسه مفهومی:

    ویژگی Standard Datacenter
    Windows Server OS ✅ ✅
    نقش‌های معمول Server ✅ ✅
    Active Directory ✅ ✅
    DNS / DHCP ✅ ✅
    File Server ✅ ✅
    قابلیت‌های پیشرفته Data Center محدودتر گسترده‌تر
    Virtualization Rights محدودتر گسترده‌تر
    مناسب برای محیط‌های Virtualized بزرگ کمتر بیشتر
    💡 نکته مهم

    جزئیات دقیق Licensing و تعداد مجاز Windows Server VMها به نسخه و شرایط Licensing بستگی دارد؛ برای تصمیم خرید باید مستندات همان نسخه بررسی شود.

    ۵. یک اشتباه مهم

    ممکن است فکر کنی:

    «اگر Datacenter نصب کنم، Server من سریع‌تر می‌شود.»

    ❌ نه.

    Edition به خودی خود باعث نمی‌شود:

    • CPU سریع‌تر شود.
    • RAM بیشتر شود.
    • Network سریع‌تر شود.

    Edition بیشتر مشخص می‌کند:

    چه قابلیت‌ها و حقوق استفاده‌ای در اختیار داری.

    ۶. Server Core و Desktop Experience

    حالا به انتخاب دوم می‌رسیم.

    در زمان نصب Windows Server معمولاً با دو حالت مهم مواجه می‌شوی:

    Server Core

    نسخه‌ای با محیط گرافیکی بسیار محدود که عمدتاً از طریق:

    • Command Line
    • PowerShell
    • Remote Management

    مدیریت می‌شود.

    تصویر ذهنی:

    Server Core
     ↓
Minimal GUI
     ↓
PowerShell / CMD / Remote Management

    Desktop Experience

    محیط گرافیکی کامل‌تری در اختیار Administrator قرار می‌دهد.

    یعنی مدیریت Server شبیه‌تر به Windows Desktop است.

    Desktop Experience
        ↓
     Full GUI
        ↓
GUI + PowerShell + CMD

    ۷. Core یا Desktop Experience؟

    انتخاب به نیاز محیط بستگی دارد.

    Server Core

    مزیت‌های مهم:

    • سطح Attack Surface کمتر
    • مصرف Resource کمتر
    • نیاز کمتر به GUI
    • مناسب برای مدیریت Remote
    • مناسب برای بسیاری از Serverهای Infrastructure

    اما:

    مدیریت آن به دانش Command Line و PowerShell بیشتری نیاز دارد.

    Desktop Experience

    مزیت اصلی:

    • مدیریت گرافیکی ساده‌تر برای Administrator

    برای محیط‌های آموزشی یا زمانی که یک ابزار به GUI نیاز دارد، می‌تواند انتخاب مناسبی باشد.

    ۸. مدل ذهنی Installation

    این دو مفهوم را با هم قاطی نکن:

    Edition
│
├── Standard
└── Datacenter

Installation Option
│
├── Server Core
└── Desktop Experience

    یعنی مثلاً می‌توانی داشته باشی:

    Windows Server Standard + Server Core

    یا:

    Windows Server Datacenter + Desktop Experience

    Edition و Installation Option دو انتخاب متفاوت هستند.

    فرآیند کلی:

    ۱۰. Installation Media

    برای نصب معمولاً به یک Installation Media نیاز داری.

    مثلاً:

    • ISO
    • USB
    • Virtual Media

    در محیط Virtualization معمولاً ISO را به Virtual Machine متصل می‌کنیم.

    Windows Server ISO
        ↓
Virtual Machine
        ↓
    Boot
        ↓
Windows Server Setup

    ۱۱. انتخاب Edition

    در Setup ممکن است Editionهای مختلف را ببینی.

    مثلاً:

    Windows Server Standard
Windows Server Standard (Desktop Experience)
Windows Server Datacenter
Windows Server Datacenter (Desktop Experience)

    در اینجا دو تصمیم مختلف در نام گزینه دیده می‌شود:

    Standard / Datacenter  +  Core / Desktop Experience

    ۱۲. انتخاب Disk

    بعد از انتخاب Installation Type، باید مشخص کنی Windows روی کدام Disk/Partition نصب شود.

    مثلاً:

    Disk 0
├── Partition 1
└── Unallocated Space

    اگر یک Disk خالی داری، می‌توانی فضای مناسب را برای نصب انتخاب کنی.

    ⚠️ هشدار

    در محیط واقعی باید این مرحله را با دقت انجام دهی، چون انتخاب یا حذف اشتباه Partition می‌تواند باعث از دست رفتن اطلاعات شود.

    ۱۳. Administrator Password

    بعد از نصب، Windows Server وارد مرحله Initial Configuration می‌شود و باید برای حساب Administrator رمز تنظیم شود.

    این حساب بسیار قدرتمند است.

    پس:

    رمز Administrator باید قوی و به‌درستی محافظت شود.

    در محیط Domain بعداً مدیریت Accountها و Administratorها را به شکل ساختاریافته‌تری یاد می‌گیریم.

    ۱۴. اولین کارها بعد از Installation

    بعد از نصب، Server هنوز لزوماً آماده Production نیست.

    معمولاً باید مواردی مثل:

    Installation
     ↓
Computer Name
     ↓
IP Configuration
     ↓
Time / Time Zone
     ↓
Updates
     ↓
Activation / Licensing
     ↓
Roles & Features
     ↓
Security Configuration
     ↓
Remote Management

    بررسی شوند.

    این موارد را در درس‌های بعدی عمیق‌تر یاد خواهی گرفت.

    ۱۵. مثال عملی

    فرض کن می‌خواهی یک Server برای یک شرکت کوچک نصب کنی.

    نیازها:

    • DNS
    • DHCP
    • File Server
    • Active Directory
    • مدیریت Remote

    برای انتخاب Edition، ممکن است:

    Standard

    کافی باشد، چون نیاز به قابلیت‌های خاص Datacenter نداری.

    برای Installation نیز اگر Administrator بتواند Server را با PowerShell و ابزارهای Remote مدیریت کند:

    Server Core

    می‌تواند انتخاب مناسبی باشد.

    در نتیجه:

    Windows Server
│
├── Edition       →  Standard
└── Installation  →  Server Core

    اما اگر محیط آموزشی یا یک Application به GUI نیاز داشته باشد:

    Windows Server
│
├── Edition       →  Standard
└── Installation  →  Desktop Experience

    ۱۶. نکته مهم درباره تغییر Core و GUI

    یک نکته عملی مهم:

    نباید فرض کنی که هر زمان خواستی می‌توانی Server Core را مثل یک Feature ساده به Desktop Experience تبدیل کنی یا برعکس.

    در نسخه‌های مدرن Windows Server، انتخاب Installation Option در Setup اهمیت دارد و تغییر بین Core و Desktop Experience ممکن است به Reinstallation نیاز داشته باشد.

    پس هنگام نصب، انتخاب را با نیاز واقعی انجام بده.

    ۱۷. اشتباهات رایج

    اشتباه ۱

    Datacenter یعنی Server قوی‌تر.

    ❌ نه.

    Edition بیشتر تفاوت در Features و Licensing ایجاد می‌کند.

    اشتباه ۲

    Server Core یعنی Windows Server بدون هیچ مدیریتی.

    ❌ نه.

    Server Core کاملاً قابل مدیریت است؛ فقط GUI کامل ندارد.

    اشتباه ۳

    Core و Standard دو Edition هستند.

    ❌ نادرست.

    Standard / Datacenter   →  Edition
Core / Desktop Experience  →  Installation Option

    اشتباه ۴

    بعد از نصب دیگر کاری لازم نیست.

    ❌ نادرست.

    بعد از نصب باید Server را برای Network، Updates، Security، Roles و Management آماده کرد.

    ۱۸. Recall کوتاه

    بدون نگاه کردن جواب بده:

    1. Standard و Datacenter چه هستند؟ → Editionهای Windows Server.
    2. Core و Desktop Experience چه هستند؟ → گزینه‌های Installation.
    3. آیا Datacenter الزاماً سریع‌تر است؟ → خیر.
    4. مزیت مهم Core چیست؟ → محیط ساده‌تر، Resource کمتر و Attack Surface کمتر.
    5. بعد از نصب چه چیزهایی باید بررسی شوند؟ → Network، Updates، Security، Name و Roles و تنظیمات اولیه.

    ۱۹. نکات مهم

    • Standard و Datacenter دو Edition مهم Windows Server هستند.
    • Datacenter قابلیت‌ها و حقوق Virtualization گسترده‌تری دارد.
    • Standard برای بسیاری از Serverهای معمول کافی است.
    • Server Core محیط GUI کامل ندارد.
    • Desktop Experience محیط گرافیکی کامل‌تری دارد.
    • Edition با Installation Option فرق دارد.
    • Core معمولاً برای Serverهای Remote-managed مناسب است.
    • انتخاب Installation Option هنگام Setup اهمیت دارد.
    • نصب پایان کار نیست؛ Initial Configuration بعد از نصب ضروری است.

    ۲۰. جمع‌بندی مفهومی

    کل درس را این‌طور ببین:

    سؤال اول:

    → Standard یا Datacenter

    سؤال دوم:

    Server را با چه محیط مدیریتی نصب کنم؟

    ۲۱. سناریوی ترکیبی

    سناریو

    یک شرکت قصد دارد Domain Controller جدیدی ایجاد کند.

    شرایط:

    • Server قرار است در Data Center اجرا شود.
    • Administratorها از طریق Remote Management آن را مدیریت می‌کنند.
    • نیاز به GUI خاصی وجود ندارد.
    • Virtualization گسترده و قابلیت‌های خاص Datacenter موردنیاز نیست.

    • A) Core و Desktop Experience

    • C) Core و Standard
    • D) GUI و CLI

    • B) Standard
    • C) Server Core ✓

    پاسخ صحیح: C — Server Core نوع Installation Option است.

    🧪 سؤال ۳ — سناریویی

    Administrator می‌گوید: «برای اینکه Server سریع‌تر شود باید Datacenter نصب کنم.»

    کدام پاسخ فنی درست‌تر است؟

    • A) درست است؛ Datacenter CPU را سریع‌تر می‌کند.
    • B) درست است؛ Datacenter RAM را افزایش می‌دهد.
    • C) خیر؛ تفاوت اصلی Edition در Features و Licensing است. ✓
    • D) Datacenter فقط برای Clientهاست.

    پاسخ صحیح: C — Edition به خودی خود Hardware Performance را افزایش نمی‌دهد.

    🧪 سؤال ۴

    شرکتی Serverهای خود را عمدتاً با PowerShell و Remote Management مدیریت می‌کند و نیاز خاصی به GUI ندارد. کدام Installation Option می‌تواند مناسب باشد؟

    • A) Server Core ✓
    • B) Desktop Experience فقط
    • C) BIOS Mode
    • D) Datacenter

    پاسخ صحیح: A — Server Core برای بسیاری از Serverهایی که Remote مدیریت می‌شوند مناسب است.

    🧪 سؤال ۵ — Troubleshooting

    Administrator هنگام نصب می‌گوید: «من Standard را انتخاب کردم، ولی چرا هنوز گزینه Server Core یا Desktop Experience را می‌بینم؟»

    علت چیست؟

    • A) Standard و Core یک مفهوم هستند.
    • B) Core/GUI مربوط به Installation Option است و Standard/Datacenter مربوط به Edition. ✓
    • C) Setup خراب شده است.
    • D) Server باید Linux باشد.

    پاسخ صحیح: B — این دو انتخاب در دو سطح متفاوت هستند.

    🧪 سؤال ۶ — سناریویی

    شخصی می‌خواهد Windows Server نصب کند و روی Disk حاوی اطلاعات مهم، بدون بررسی Partitionها گزینه Delete را انتخاب می‌کند. مشکل اصلی چیست؟

    • A) باعث افزایش RAM می‌شود.
    • B) ممکن است اطلاعات موجود روی Disk از بین برود. ✓
    • C) Server را به Datacenter تبدیل می‌کند.
    • D) DNS را فعال می‌کند.

    پاسخ صحیح: B — مدیریت Disk و Partition در زمان Installation باید با دقت انجام شود.

    🧪 سؤال ۷

    کدام ترتیب، مسیر کلی منطقی نصب Windows Server را بهتر نشان می‌دهد؟

    • A) Roles → Disk → Boot → Edition → Install
    • B) Boot Media → Setup → Edition/Installation Option → Disk → Install → Initial Configuration ✓
    • C) DNS → DHCP → Disk → Setup
    • D) Active Directory → Installation → BIOS

    پاسخ صحیح: B — ابتدا سیستم از Installation Media بوت می‌شود، سپس Setup، انتخاب Edition/Installation Option، انتخاب Disk و نصب انجام می‌شود و بعد Initial Configuration صورت می‌گیرد.

    Windows Server Core

    دوره جامع Windows Server & Active Directory · نسخه ۲۰۲۲/۲۰۲۵

    ۱. اهداف یادگیری

    در پایان این درس باید بتوانی:

    • دقیقاً توضیح بدهی Server Core چیست و چه تفاوتی با Desktop Experience دارد.
    • مدل مدیریت Server Core با PowerShell، CMD و ابزارهای Remote را درک کنی.
    • تنظیمات اولیه Server Core را انجام بدهی.
    • Server Core را از راه دور مدیریت کنی.
    • خطاهای رایج در مدیریت Server Core را تشخیص بدهی.

    ۲. معرفی

    در درس قبل دیدیم که هنگام نصب Windows Server می‌توانی بین:

    • Server Core
    • Desktop Experience

    انتخاب کنی.

    حالا می‌خواهیم خود Server Core را بشناسیم.

    ایده اصلی بسیار ساده است:

    Server Core یک نصب کمینه‌تر از Windows Server است که محیط گرافیکی کامل Desktop Experience را ندارد.

    یعنی به‌جای اینکه Server را با پنجره‌ها و ابزارهای گرافیکی مدیریت کنی، بیشتر با:

    PowerShell
CMD
Remote Management

    کار می‌کنی.

    مدل ذهنی:

    Desktop Experience
│
├── GUI
├── PowerShell
└── CMD

Server Core
│
├── PowerShell
├── CMD
└── Remote Management

    ۳. چرا Server Core؟

    یک Server معمولاً قرار نیست مثل یک کامپیوتر شخصی برای کاربر استفاده شود.

    مثلاً یک Domain Controller بیشتر این کار را انجام می‌دهد:

    Client
│
├── Login
├── DNS
└── Authentication
│
▼
Domain Controller

    برای چنین Serverی معمولاً لازم نیست GUI کامل داشته باشیم.

    بنابراین Server Core کمک می‌کند محیط Server ساده‌تر و کمینه‌تر باشد.

    مزایای مهم:

    • مصرف Resource کمتر
    • اجزای کمتر
    • Attack Surface کمتر
    • مناسب برای Remote Management
    • مناسب برای Serverهای Infrastructure

    اما در مقابل:

    Administrator باید با Command Line و PowerShell راحت باشد.

    ۴. Server Core بدون GUI کامل

    وقتی وارد Server Core می‌شوی، انتظار Desktop معمولی Windows را نداشته باش.

    مثلاً:

    ┌──────────────────────────────┐
│  Command Prompt / PowerShell │
│                              │
│  C:\Windows\System32>        │
│                              │
└──────────────────────────────┘

    ممکن است پنجره Command Prompt را ببینی، اما:

    • Desktop کامل
    • Start Menu معمولی
    • File Explorer کامل
    • بسیاری از ابزارهای GUI

    در دسترس نیستند.

    این به معنی «غیرقابل مدیریت بودن» نیست.

    ۵. مدیریت Server Core

    چهار روش ذهنی مهم داشته باش:

    ۶. SConfig

    یکی از ابزارهای بسیار مهم در Server Core:

    SConfig

    یا Server Configuration Tool است.

    SConfig یک رابط متنی برای انجام بسیاری از تنظیمات اولیه Server است.

    مثلاً می‌توانی از آن برای کارهایی مانند:

    • تنظیم Computer Name
    • تنظیم Network
    • تنظیمات Windows Update
    • فعال‌سازی Remote Management
    • تنظیمات Domain/Workgroup

    استفاده کنی.

    در بسیاری از نسخه‌های Windows Server، می‌توانی با اجرای sconfig آن را باز کنی.

    مدل ذهنی:

    Server Core
     ↓
  sconfig
     ↓
Initial Configuration

    ۷. تنظیم Computer Name

    فرض کن Server بعد از نصب نام تصادفی دارد و می‌خواهی آن را به DC01 تغییر دهی.

    می‌توانی از SConfig یا PowerShell استفاده کنی.

    PowerShell:

    PowerShell Rename-Computer 
    Rename-Computer -NewName "DC01"

    بعد از تغییر نام، معمولاً Restart لازم است.

    PowerShell Restart-Computer 
    Restart-Computer

    ۸. تنظیم IP

    Serverهای Infrastructure معمولاً باید IP مشخص و قابل پیش‌بینی داشته باشند.

    مثلاً:

    IP Address:   192.168.10.10
Subnet Mask:  255.255.255.0
Gateway:      192.168.10.1
DNS:          192.168.10.10

    در PowerShell می‌توان با Cmdletهای شبکه تنظیمات را انجام داد.

    ابتدا Interfaceها:

    PowerShell Get-NetAdapter 
    Get-NetAdapter

    مثلاً خروجی:

    Name      Status
----      ------
Ethernet  Up

    بعد IP:

    PowerShell New-NetIPAddress 
    New-NetIPAddress `
  -InterfaceAlias "Ethernet" `
  -IPAddress 192.168.10.10 `
  -PrefixLength 24 `
  -DefaultGateway 192.168.10.1

    و DNS:

    PowerShell Set-DnsClientServerAddress 
    Set-DnsClientServerAddress `
  -InterfaceAlias "Ethernet" `
  -ServerAddresses 192.168.10.10

    ۹. چرا PrefixLength؟

    در مثال بالا:

    192.168.10.10/24

    عدد 24 معادل Subnet Mask زیر است:

    255.255.255.0

    فعلاً لازم نیست وارد Subnetting عمیق شویم؛ فقط بدان:

    PrefixLength مشخص‌کننده اندازه Network Prefix است.

    ۱۲. نصب Role و Feature

    ۱۳. PowerShell در Server Core

    ۱۴. Remote Management

    قرار نیست همیشه کنار Server Core بنشینی و Command وارد کنی.

    ۱۵. Server Core و Windows Admin Center

    Windows Admin Center (WAC) یک ابزار مدیریتی مبتنی بر Web است که می‌تواند برای مدیریت Windows Server استفاده شود.

    ۱۶. Server Core و امنیت

    یکی از دلایل استفاده از Server Core:

    کاهش سطح حمله (Attack Surface) است.

    چون اجزای غیرضروری GUI و برخی Components وجود ندارند، تعداد بخش‌هایی که می‌توانند نیاز به Patch یا در معرض حمله باشند کاهش می‌یابد.

    اما:

    Server Core به معنی «امنیت کامل» نیست.

    هنوز باید:

    • Firewall
    • Updates
    • Authentication
    • Permissions
    • Network Security

    به‌درستی مدیریت شوند.

    ❌ برعکس؛ PowerShell یکی از ابزارهای اصلی مدیریت آن است.

    اشتباه ۲

    ❌ نادرست.

    اشتباه ۴

    Server Core خودش به‌صورت خودکار امن است.

    1. Server Core چیست؟ → نصب کمینه‌تر Windows Server بدون Desktop Experience کامل.

    • Server Core = Windows Server بدون Desktop Experience کامل.

    Windows Server Upgrade

    دوره جامع Windows Server & Active Directory · نسخه ۲۰۲۲/۲۰۲۵

    ۱. اهداف یادگیری

    در پایان این درس باید بتوانی:

    • تفاوت Upgrade و Migration را در عمل تشخیص بدهی.
    • شرایط و محدودیت‌های مهم In-Place Upgrade را بشناسی.
    • مسیر کلی Upgrade یک Windows Server را انجام بدهی.
    • قبل از Upgrade، موارد مهمی مثل Backup، Compatibility و Version را بررسی کنی.
    • خطاهای رایج و روش Troubleshooting Upgrade را بشناسی.

    ۲. معرفی

    فرض کن یک سازمان Windows Server 2019 دارد و می‌خواهد به Windows Server 2025 منتقل شود.

    دو راه کلی دارد:

    روش ۱: In-Place Upgrade

    Server 2019
    ↓
همان Server
    ↓
Server 2025

    یا:

    روش ۲: Migration

    Server 2019
    ↓
New Server
    ↓
Server 2025

    در این درس تمرکز ما روی Upgrade است.

    ۳. Upgrade چیست؟

    Upgrade یعنی نسخه Windows Server موجود را به نسخه جدیدتر ارتقا بدهیم، در حالی که همان Installation و همان Server را تا حد امکان حفظ می‌کنیم.

    مثلاً:

    Windows Server 2019
        ↓
Windows Server 2022

    یا در یک مسیر پشتیبانی‌شده:

    Windows Server 2022
        ↓
Windows Server 2025

    در Upgrade، هدف این است که:

    • OS جدید شود.
    • تنظیمات موجود تا حد امکان حفظ شوند.
    • Applicationها و Roleهای موجود باقی بمانند.

    اما این به معنی «بدون ریسک بودن» نیست.

    ۴. In-Place Upgrade چیست؟

    وقتی همان Server را Upgrade می‌کنی، به آن:

    In-Place Upgrade

    می‌گوییم.

    مثلاً:

    Before
┌────────────────────┐
│ Physical / VM      │
│ Windows Server 2019│
│ AD / DNS / App     │
└────────────────────┘
         ↓
      Upgrade
         ↓
┌────────────────────┐
│ Physical / VM      │
│ Windows Server 2025│
│ AD / DNS / App     │
└────────────────────┘

    Hardware یا VM همان است؛ سیستم‌عامل ارتقا پیدا می‌کند.

    ۵. Upgrade با Migration چه فرقی دارد؟

    این تفاوت را باید خیلی خوب بلد باشی.

    Upgrade

    Old OS
   ↓
New OS

Same Server

    Migration

    Old Server
    ↓
New Server
    ↓
Move Roles / Data / Services

    مثلاً:

    Server01
Windows Server 2019
       │
       │ Migration
       ▼
Server02
Windows Server 2025

    در Migration معمولاً Server جدید جداگانه ایجاد می‌کنی.

    ۶. آیا هر Version را می‌توان مستقیم Upgrade کرد؟

    خیر.

    این یکی از مهم‌ترین نکات Upgrade است.

    مسیر Upgrade به مواردی مثل:

    • Version فعلی
    • Version مقصد
    • Edition
    • Architecture
    • Installation Option
    • Language
    • Role/Application Compatibility

    وابسته است.

    بنابراین:

    قبل از Upgrade باید Supported Upgrade Path را بررسی کنی.

    مثلاً نباید فرض کنی:

    هر نسخه قدیمی
      ↓
هر نسخه جدید

    مستقیماً قابل Upgrade است.

    ۷. Edition Compatibility

    Edition نیز اهمیت دارد.

    مثلاً اگر Server فعلی Standard باشد، باید بررسی کنی مسیر انتقال به Edition مقصد چگونه است.

    مدل ذهنی:

    Current
│
├── Version
├── Edition
├── Architecture
└── Installation Type
         ↓
 Compatibility Check
         ↓
 Supported Upgrade?

    ۸. Server Core و Desktop Experience

    Installation Option نیز مهم است.

    مثلاً:

    Server Core
    ↓
    ?
    ↓
Desktop Experience

    نباید فرض کنی هر تبدیل Core ↔ Desktop Experience در هر Version و مسیر Upgrade پشتیبانی می‌شود.

    در برنامه‌ریزی Upgrade باید مستندات همان Version بررسی شود.

    ۹. قبل از Upgrade چه کنیم؟

    یکی از مهم‌ترین قسمت‌های درس:

    Preparation

    قبل از Upgrade باید وضعیت فعلی را بررسی کنی.

    چک‌لیست ذهنی:

    Current Version
      ↓
Hardware / VM
      ↓
   Edition
      ↓
 Applications
      ↓
Roles / Features
      ↓
   Drivers
      ↓
 Disk Space
      ↓
   Backup
      ↓
 Compatibility
      ↓
 Upgrade Path

    ۱۰. Backup

    قبل از Upgrade باید Backup مناسب داشته باشی.

    چرا؟

    چون Upgrade یک تغییر بزرگ روی سیستم‌عامل است.

    اگر مشکلی ایجاد شود، باید بتوانی Recovery انجام دهی.

    مدل ساده:

    Before Upgrade
      │
      ↓
    Backup
      │
      ↓
   Upgrade
      │
   ┌──┴──┐
   │     │
Success  Failure
   │     │
Continue Recovery Plan
    ⚠️ هشدار

    Backup با داشتن یک Copy معمولی از چند فایل یکی نیست. برای Serverهای مهم باید Recovery Strategy واقعی داشته باشی.

    ۱۱. بررسی Disk Space

    Upgrade به فضای کافی نیاز دارد.

    اگر Disk تقریباً پر باشد:

    C: 99% Full

    شروع Upgrade ایده خوبی نیست.

    ابتدا:

    • فضای آزاد
    • Temporary Files
    • Logs
    • Application Data

    را بررسی می‌کنی.

    ۱۲. بررسی Application Compatibility

    فرض کن روی Server یک Application حیاتی اجرا می‌شود.

    قبل از Upgrade باید بررسی کنی:

    آیا Application با OS جدید سازگار است؟

    مثلاً:

    Windows Server 2019
      │
      └── Application X
              │
              ↓
    Supports Server 2025?

    اگر جواب مشخص نباشد، Upgrade مستقیم می‌تواند خطرناک باشد.

    ۱۳. بررسی Drivers و Hardware

    در Physical Server:

    • Storage Controller
    • NIC
    • Firmware
    • Driver

    مهم هستند.

    در Virtual Machine نیز باید:

    • Hypervisor Compatibility
    • Virtual Hardware
    • Integration Components / Drivers

    بررسی شوند.

    ۱۴. نقش‌های حساس

    همه Serverها شرایط یکسانی ندارند.

    مثلاً یک:

    File Server

    با یک:

    Domain Controller

    از نظر Upgrade Risk یکسان نیست.

    ⚠️ هشدار

    در Serverهای مهم Domain، DNS، Cluster و Applicationهای حیاتی باید مستندات و روش مناسب Upgrade/Migration دقیقاً بررسی شود. به‌خصوص برای Domain Controller نباید بدون طراحی و بررسی اقدام کنی.

    ۱۵. مراحل کلی In-Place Upgrade

    مدل کلی:

    ۱۶. شروع Setup

    برای In-Place Upgrade معمولاً Installation Media نسخه مقصد را در اختیار داری.

    مثلاً:

    Windows Server 2025 ISO
          ↓
Existing Windows Server
          ↓
      Run Setup
    ⚠️ نکته مهم

    اگر قصد Upgrade داری، باید Setup را از داخل Windows فعلی به شکل مناسب اجرا کنی؛ صرفاً Boot کردن از ISO و نصب مجدد، همان In-Place Upgrade نیست.

    ۱۷. انتخاب Upgrade

    در مراحل Setup ممکن است گزینه‌هایی مربوط به حفظ اطلاعات و برنامه‌ها ببینی.

    برای Upgrade معمولاً هدف چیزی در این مفهوم است:

    Keep files, settings, and applications

    در حالی که نصب Clean مسیر متفاوتی دارد.

    مدل ذهنی:

    Setup
│
├── Upgrade
│     ↓
│   Keep existing environment
│
└── Clean Install
      ↓
   Fresh OS

    ۱۸. Upgrade یا Clean Install؟

    Upgrade

    مزیت:

    • تنظیمات و Applicationها تا حد امکان حفظ می‌شوند.
    • زمان انتقال بعضی Serverها کمتر می‌شود.

    ریسک:

    • مشکلات قدیمی ممکن است به سیستم جدید منتقل شوند.
    • Compatibility Issues ممکن است ایجاد شود.
    • Troubleshooting پیچیده‌تر شود.

    Clean Install

    سیستم‌عامل از ابتدا نصب می‌شود.

    مزیت:

    • محیط تمیز
    • حذف Configurationهای قدیمی

    اما:

    • نیاز به نصب و تنظیم مجدد
    • نیاز به Migration Data/Role/Application

    دارد.

    باید Verify کنی:

   Roles

    winver

    Get-ComputerInfo

    برای بررسی اطلاعات سیستم استفاده می‌شود.

    ۲۰. Troubleshooting

    فرض کن Upgrade تمام شده، ولی Application اجرا نمی‌شود.

    نباید فوراً نتیجه بگیری:

    «Windows خراب است.»

    مرحله‌به‌مرحله بررسی کن:

    Application Service

        ↓

        ↓

        ↓

    ۲۱. یک نکته بسیار مهم: Test Before Production

    اگر Server مهم است، بهتر است قبل از Upgrade واقعی:

    Production Server
        ↓

        ↓
    Test Upgrade
        ↓
  Identify Problems
        ↓

    را در نظر بگیری.

    به‌خصوص برای:

    • Applicationهای حساس
    • Domain Services
    • Database
    • Serverهای حیاتی

    این کار بسیار ارزشمند است.

    ۲۲. اشتباهات رایج

    اشتباه ۱

    هر Windows Server را می‌توان مستقیماً به هر نسخه جدید Upgrade کرد.

    ❌ خیر. Supported Upgrade Path باید بررسی شود.

    اشتباه ۲

    Upgrade یعنی نصب مجدد Windows.

    ❌ نه دقیقاً. Upgrade تلاش می‌کند Installation موجود را به نسخه جدید منتقل کند.

    اشتباه ۳

    Backup لازم نیست چون Upgrade رسمی Microsoft است.

    ❌ بسیار خطرناک. قبل از تغییر بزرگ باید Recovery Plan داشته باشی.

    اشتباه ۴

    بعد از Upgrade اگر Windows بالا آمد، کار تمام است.

    ❌ خیر. Application، Services، Network، Roles و Event Logs باید بررسی شوند.

    ۲۳. Recall کوتاه

    1. In-Place Upgrade چیست؟ → ارتقای OS روی همان Server.
    2. Migration چیست؟ → انتقال Workload/Service به Server یا محیط دیگر.
    3. مهم‌ترین کار قبل از Upgrade؟ → بررسی Compatibility، Supported Path و داشتن Backup/Recovery Plan.
    4. آیا همه Versionها مستقیم Upgrade می‌شوند؟ → خیر.
    5. بعد از Upgrade چه می‌کنیم؟ → Verification و Testing.

    ۲۴. نکات مهم

    • Upgrade ≠ Migration
    • In-Place Upgrade روی همان Server انجام می‌شود.
    • قبل از Upgrade باید Supported Path بررسی شود.
    • Version، Edition و Installation Option مهم هستند.
    • Application Compatibility باید بررسی شود.
    • Backup و Recovery Plan ضروری‌اند.
    • فضای Disk و Driver/Hardware باید بررسی شوند.
    • Serverهای حساس نیاز به برنامه‌ریزی دقیق‌تر دارند.
    • بعد از Upgrade باید Services، Roles، Applications و Network تست شوند.
    • Test Upgrade در محیط Lab می‌تواند ریسک را کاهش دهد.

    ۲۵. جمع‌بندی مفهومی

    Upgrade را مثل تعویض موتور یک ماشین در نظر بگیر:

    آیا می‌خواهیم همان Server را ارتقا دهیم یا Workload را به Server جدید منتقل کنیم؟

    پاسخ صحیح: A

    🧪 سؤال ۵ — Troubleshooting

    بعد از Upgrade، Windows Server بالا می‌آید ولی یک Application اجرا نمی‌شود. اولین رویکرد مناسب چیست؟

    • A) فوراً Server را Format کنیم.
    • B) Service، Dependencies، Event Logs و Compatibility را بررسی کنیم. ✓
    • C) تمام Userها را حذف کنیم.
    • D) IP را تصادفی تغییر دهیم.

    پاسخ صحیح: B — Troubleshooting باید مرحله‌ای و مبتنی بر شواهد باشد.

    🧪 سؤال ۶ — سناریویی

    یک Server مهم قرار است Upgrade شود. Administrator می‌گوید: «چون Setup رسمی Microsoft است، Backup لازم نیست.»

    کدام گزینه صحیح است؟

    • A) درست است.
    • B) Backup فقط برای Clientها لازم است.
    • C) قبل از تغییر مهم باید Backup و Recovery Plan وجود داشته باشد. ✓
    • D) Backup باعث جلوگیری از Upgrade می‌شود.

    پاسخ صحیح: C — Upgrade یک تغییر مهم در سیستم‌عامل است و باید امکان Recovery در نظر گرفته شود.

    🧪 سؤال ۷ — Troubleshooting

    بعد از Upgrade، Server روشن شده اما کاربران نمی‌توانند به File Share متصل شوند. کدام بررسی منطقی‌تر است؟

    • A) فقط Wallpaper را بررسی کنیم.
    • B) Network، سرویس‌های مربوط، File Sharing، Permissions و Event Logs را بررسی کنیم. ✓
    • C) Server را فوراً خاموش کنیم.
    • D) Edition را بدون بررسی تغییر دهیم.

    پاسخ صحیح: B — بعد از Upgrade باید سرویس‌های واقعی Server و مسیر دسترسی Clientها را Verification کنیم.

    Windows Server Environment

    دوره جامع Windows Server & Active Directory · نسخه ۲۰۲۲/۲۰۲۵

    ۱. اهداف یادگیری

    در پایان این درس باید بتوانی:

    • اجزای اصلی یک Windows Server Environment را بشناسی.
    • تفاوت Server Role، Role Service و Feature را بفهمی.
    • رابطه Server، Client، Network، DNS و Active Directory را درک کنی.
    • مفهوم Workgroup و Domain را در تصویر کلی محیط Windows Server جای بدهی.
    • یک Server را از مرحله نصب تا تبدیل شدن به یک Server واقعی در شبکه تصور کنی.

    ۲. معرفی

    تا اینجا درباره خود Windows Server صحبت کردیم:

    Windows Server
     ↓
   Edition
     ↓
Installation
     ↓
Core / Desktop Experience
     ↓
  Upgrade

    حالا باید یک قدم عقب‌تر برویم و بپرسیم:

    Windows Server در یک شبکه واقعی دقیقاً چه جایگاهی دارد؟

    یک Server به‌تنهایی معنای زیادی ندارد.

    Server زمانی مفید است که بتواند برای Clientها و Serverهای دیگر Service ارائه کند.

    مثلاً:

         Network
        │
┌───────┼───────┐
↓       ↓       ↓
Client Client Client
│       │       │
└───────┼───────┘
        ↓
  Windows Server
        │
┌───────┼───────┐
↓       ↓       ↓
DNS    DHCP     AD

    این همان Windows Server Environment است.

    ۳. Server فقط یک کامپیوتر نیست

    از نظر Hardware، Server می‌تواند یک کامپیوتر باشد.

    اما از نظر Network:

    Server یعنی سیستمی که Service ارائه می‌کند.

    DNS Server

    نام را به IP تبدیل می‌کند:

    server.example.com
        ↓
   192.168.10.10

    DHCP Server

    به Clientها تنظیمات IP می‌دهد:

    Client
   ↓
 DHCP
   ↓
IP + Gateway + DNS

    Active Directory Domain Controller

    احراز هویت و مدیریت هویت Domain را انجام می‌دهد.

    File Server

    فایل‌ها را برای کاربران شبکه ارائه می‌کند.

    پس:

    Server بودن بیشتر به Role و Service مربوط است، نه فقط به سخت‌افزار.

    ۴. Server Role چیست؟

    Server Role مجموعه‌ای از قابلیت‌ها و سرویس‌هایی است که Server برای انجام یک وظیفه مشخص ارائه می‌کند.

    مثلاً:

    Windows Server
│
├── DNS Server Role
├── DHCP Server Role
├── File Services
└── AD DS

    مثلاً وقتی روی یک Server نقش DNS Server نصب می‌کنی، Server می‌تواند سرویس DNS ارائه کند.

    ۵. Role Service چیست؟

    بعضی Roleها خودشان از چند بخش تشکیل می‌شوند.

    به این بخش‌ها می‌توان Role Service گفت.

    مدل ذهنی:

    Server Role
│
├── Role Service 1
├── Role Service 2
└── Role Service 3

    یعنی:

    Role یک قابلیت/وظیفه بزرگ‌تر است و Role Service می‌تواند بخشی از آن Role باشد.

    لازم نیست فعلاً فهرست همه Role Serviceها را حفظ کنی؛ مفهوم مهم‌تر است.

    ۶. Feature چیست؟

    Feature یک قابلیت اضافی Windows Server است که الزاماً یک Server Role کامل نیست.

    مدل ساده:

    Windows Server
│
├── Roles
│   ├── DNS
│   ├── DHCP
│   └── AD DS
│
└── Features
    ├── ابزارها
    └── قابلیت‌های اضافی

    بنابراین:

    Role ≠ Feature

    ۷. نصب و مشاهده Roles و Features

    در PowerShell می‌توانی Roleها و Featureها را مشاهده کنی:

    PowerShell Get-WindowsFeature 
    Get-WindowsFeature

    مثلاً برای نصب یک Feature یا Role:

    PowerShell Install-WindowsFeature 
    Install-WindowsFeature -Name DNS

    یا برای مشاهده وضعیت DNS:

    PowerShell Get-WindowsFeature 
    Get-WindowsFeature -Name DNS

    این دستورات در Server Core نیز بسیار کاربردی هستند.

    ۸. Server و Client

    یک محیط Server معمولاً شامل دو گروه اصلی است:

    Server
   ↓
Service Provider

Client
   ↓
Service Consumer

    مثلاً:

    File Server
    │
File Share
    │
┌───┼───┐
↓   ↓   ↓
C1  C2  C3

    Clientها از سرویس Server استفاده می‌کنند.

    البته یک Server می‌تواند همزمان از سرویس Server دیگری هم استفاده کند.

    ۹. Network Interface

    Server برای ارتباط با شبکه به NIC یا Network Interface Card نیاز دارد.

    مدل:

    Windows Server
      │
      ↓
     NIC
      │
      ↓
    Switch
      │
├── Client
├── Client
└── Other Server

    در Serverهای واقعی ممکن است چند NIC داشته باشیم.

    مثلاً:

    Server
├── NIC 1 → Management
├── NIC 2 → Production Network
└── NIC 3 → Storage

    طراحی دقیق به معماری شبکه بستگی دارد.

    ۱۰. IP Address

    Server برای ارتباط شبکه‌ای معمولاً به IP نیاز دارد.

    مثلاً:

    Server:  192.168.10.10
Client:  192.168.10.20

    برای ارتباط:

    Client
192.168.10.20
      │
      ↓
   Network
      │
      ↓
Server
192.168.10.10

    در محیط‌های Server، مخصوصاً برای Infrastructure Serverها، استفاده از IP قابل پیش‌بینی اهمیت زیادی دارد.

    ۱۱. DNS در محیط Windows Server

    DNS یکی از مهم‌ترین اجزای این Environment است.

    مثلاً Client می‌خواهد به dc01.example.local متصل شود.

    به‌جای اینکه IP را حفظ کند، DNS می‌تواند آن را پیدا کند:

    dc01.example.local
        ↓
       DNS
        ↓
   192.168.10.10

    به همین دلیل در محیط‌های Domain، DNS اهمیت بسیار زیادی دارد.

    بعداً یک بخش کامل را به DNS اختصاص خواهیم داد.

    ۱۲. DHCP

    DHCP وظیفه دارد تنظیمات شبکه را به Clientها اختصاص دهد.

    مثلاً:

    Client
   │
   │ DHCP Request
   ↓
DHCP Server
   │
   └── IP: 192.168.10.20
       Mask: /24
       Gateway: 192.168.10.1
       DNS: 192.168.10.10

    پس DHCP باعث می‌شود لازم نباشد IP همه Clientها را دستی تنظیم کنیم.

    ۱۳. Active Directory

    در محیط سازمانی، یکی از مهم‌ترین اجزای Windows Server:

    Active Directory Domain Services (AD DS)

    است.

    AD DS برای مدیریت هویت و منابع در یک Domain استفاده می‌شود.

    مدل ساده:

    Domain
│
┌────────┼────────┐
↓        ↓        ↓
Users Computers Groups
        │
        ↓
  Authentication

    Serverی که AD DS را ارائه می‌کند و نقش Domain Controller دارد:

    Domain Controller (DC)

    نامیده می‌شود.

    ۱۴. Domain Controller

    یک DC می‌تواند وظایفی مثل:

    • Authentication
    • User Management
    • Computer Management
    • Group Management
    • Directory Services

    را انجام دهد.

    مثلاً وقتی کاربر وارد سیستم Domain می‌شود:

    User
  ↓
Login
  ↓
Domain Controller
  ↓
Authentication
  ↓
Access

    این موضوع بعداً در بخش Active Directory به‌صورت کامل بررسی خواهد شد.

    ۱۵. Workgroup در مقابل Domain

    فعلاً فقط تصویر کلی را بساز.

    Workgroup

    هر کامپیوتر بیشتر به‌صورت مستقل مدیریت می‌شود:

    PC1    PC2    PC3
│      │      │
Local  Local  Local
Accounts Accounts Accounts

    Domain

    مدیریت متمرکزتر می‌شود:

        Domain
       │
Domain Controller
       │
┌──────┼──────┐
↓      ↓      ↓
PC1    PC2    PC3

    در Domain، User و Computer می‌توانند تحت مدیریت مرکزی قرار بگیرند.

    ۱۶. Windows Server Environment در یک تصویر

    حالا تمام مفاهیم را کنار هم بگذار:

         Network
        │
┌───────┼───────┐
↓       ↓       ↓
Client Client Client
│       │       │
└───────┼───────┘
        │
      Switch
        │
┌───────┼───────┐
↓       ↓       ↓
DC/DNS  DHCP  File Server
│       │       │
└───────┼───────┘
        │
   Windows Server

    البته در محیط واقعی ممکن است DNS، DHCP، AD و File Server روی Serverهای جداگانه باشند.

    ۱۷. Server Manager

    در Windows Server، یکی از ابزارهای مدیریتی مهم:

    Server Manager

    است.

    Server Manager امکان مدیریت بسیاری از:

    • Roles
    • Features
    • Servers
    • Services
    • Configuration

    را فراهم می‌کند.

    در Desktop Experience استفاده از GUI آن راحت‌تر است.

    در Server Core معمولاً مدیریت از طریق:

    • PowerShell
    • SConfig
    • Remote Tools

    انجام می‌شود.

    ۱۸. Local و Remote Management

    یک Administrator ممکن است Server را از خود Server مدیریت کند:

    Administrator
      ↓
   Server

    یا از یک کامپیوتر مدیریتی:

    Administrator PC
      ↓
Remote Management
      ↓
   Server

    این مدل دوم برای Server Core بسیار مهم است.

    ۱۹. Server Environment فقط یک Server نیست

    در یک شرکت متوسط ممکن است چنین معماری‌ای ببینی:

           Network
          │
┌─────────┼─────────┐
↓         ↓         ↓
DC1       DC2    File Server
AD/DNS   AD/DNS
│         │         │
└─────────┼─────────┘
          │
        DHCP
          │
    ┌─────┼─────┐
    ↓     ↓     ↓
   PC1   PC2   PC3

    داشتن چند Server برای یک Role هم می‌تواند برای Redundancy / Availability مفید باشد.

    مثلاً دو Domain Controller:

    DC1 ←→ DC2

    اگر یکی مشکل پیدا کند، دیگری می‌تواند بخشی از سرویس Domain را ادامه دهد.

    جزئیات Replication را در بخش Active Directory یاد خواهیم گرفت.

    ۲۰. چرا این مدل ذهنی مهم است؟

    چون در درس‌های بعدی هر موضوعی که می‌خوانی، جای مشخصی در این نقشه دارد.

    مثلاً:

    Remote Management    →  مدیریت Server
NIC Teaming          →  Network
Storage / RAID       →  Storage
Sharing / NTFS       →  File Server
DNS                  →  Name Resolution
Active Directory     →  Identity / Domain
DHCP                 →  IP Configuration

    پس مباحث دوره پراکنده نیستند؛ همه بخشی از یک Windows Server Environment هستند.

    ۲۱. اشتباهات رایج

    اشتباه ۱

    Server یعنی حتماً یک کامپیوتر خیلی قدرتمند.

    ❌ نه.

    Server از نظر نقش یعنی سیستمی که Service ارائه می‌کند.

    اشتباه ۲

    DNS و DHCP فقط روی Router اجرا می‌شوند.

    ❌ نه.

    Windows Server می‌تواند DNS و DHCP Server باشد.

    اشتباه ۳

    هر Server باید فقط یک Role داشته باشد.

    ❌ نه.

    یک Server می‌تواند چند Role و Feature داشته باشد، هرچند در طراحی Production ممکن است برای امنیت، Performance یا Availability نقش‌ها جدا شوند.

    اشتباه ۴

    Domain یعنی فقط یک نام برای شبکه.

    ❌ نه.

    Windows Domain یک محیط مدیریتی و امنیتی مبتنی بر Active Directory است.

    ۲۲. Recall کوتاه

    1. Role چیست؟ → مجموعه قابلیت‌هایی برای ارائه یک وظیفه Server.
    2. Feature چیست؟ → قابلیت اضافی Windows Server که لزوماً یک Role کامل نیست.
    3. DC چیست؟ → Domain Controller؛ Server ارائه‌دهنده AD DS.
    4. DNS چه می‌کند؟ → Name Resolution.
    5. DHCP چه می‌کند؟ → تنظیمات شبکه را به Clientها اختصاص می‌دهد.
    6. Server Environment چیست؟ → مجموعه Serverها، Clientها، Network و Services که با هم یک محیط کاری را تشکیل می‌دهند.

    ۲۳. نکات مهم

    • Server فقط Hardware نیست؛ Service Provider است.
    • Role وظیفه اصلی Server را مشخص می‌کند.
    • Feature یک قابلیت اضافی است.
    • Clientها از سرویس Server استفاده می‌کنند.
    • NIC رابط Server با Network است.
    • DNS برای Name Resolution استفاده می‌شود.
    • DHCP تنظیمات IP را به Clientها می‌دهد.
    • AD DS هویت و مدیریت Domain را فراهم می‌کند.
    • Domain Controller نقش اصلی در Active Directory دارد.
    • Serverها می‌توانند Local یا Remote مدیریت شوند.
    • یک Server Environment از چندین Component تشکیل شده است.

    ۲۴. جمع‌بندی مفهومی

    اگر کل درس را به یک زنجیره تبدیل کنیم:

    Hardware / VM
      ↓
 Windows Server
      ↓
Network Configuration
      ↓
 Roles + Features
      ↓
   Services
      ↓
   Clients
      ↓
Users + Applications

    و در یک محیط سازمانی:

    Windows Server Environment
│
┌───────────────────┼───────────────────┐
↓                   ↓                   ↓
Network          Services            Identity
│                   │                   │
NIC/IP     DNS/DHCP/File            AD DS
│                   │                   │
└───────────────────┼───────────────────┘
                    ↓
                 Clients

    یعنی Windows Server یک قطعه جدا از شبکه نیست؛ بخشی از یک سیستم بزرگ‌تر است.

    ۲۵. سناریوی ترکیبی

    سناریو

    یک شرکت ۳۰ کاربر دارد.

    نیازهای شرکت:

    • Login مرکزی کاربران
    • IP خودکار برای Clientها
    • Name Resolution
    • File Sharing

    مرحله ۱ — Identity

    برای Login مرکزی:

    AD DS
   ↓
Domain Controller

    مرحله ۲ — Name Resolution

    برای پیدا کردن Serverها و Clientها:

    DNS

    مرحله ۳ — IP Configuration

    برای اختصاص خودکار IP:

    DHCP

    مرحله ۴ — File Sharing

    برای ذخیره و اشتراک فایل:

    File Server

    نتیجه

    می‌توان معماری ساده‌ای مانند این داشت:

         Network
        │
   ┌────┴────┐
   ↓         ↓
  DC1   File Server
AD DS + DNS
   │         │
   └────┬────┘
        │
      DHCP
        │
   ┌────┼────┐
   ↓    ↓    ↓
  PC1  PC2  PC3

    حالا اگر فردا درباره DNS بخوانی، می‌دانی DNS کجای این معماری قرار دارد.

    🧪 سؤال ۱

    کدام گزینه مفهوم Server را بهتر توضیح می‌دهد؟

    • A) فقط کامپیوتری با RAM زیاد
    • B) سیستمی که Services را برای Clientها یا سیستم‌های دیگر ارائه می‌کند ✓
    • C) فقط یک کامپیوتر با Linux
    • D) فقط یک Physical Machine

    پاسخ صحیح: B — Server از نظر نقش، Service ارائه می‌کند و الزاماً به Physical بودن وابسته نیست.

    🧪 سؤال ۲

    کدام گزینه تفاوت Role و Feature را بهتر بیان می‌کند؟

    • A) هیچ تفاوتی ندارند.
    • B) Role یک وظیفه اصلی Server است و Feature یک قابلیت اضافی است. ✓
    • C) Feature فقط روی Client نصب می‌شود.
    • D) Role فقط Hardware است.

    پاسخ صحیح: B

    🧪 سؤال ۳ — سناریویی

    کاربران یک شرکت باید بتوانند با یک حساب Domain وارد کامپیوترهای مختلف شوند. کدام Component در این سناریو نقش اصلی دارد؟

    • A) DHCP
    • B) DNS فقط
    • C) Active Directory Domain Services ✓
    • D) RAID

    پاسخ صحیح: C — AD DS سرویس Directory و Identity مربوط به Domain را فراهم می‌کند.

    🧪 سؤال ۴

    DHCP عمدتاً چه کاری انجام می‌دهد؟

    • A) تبدیل نام به IP
    • B) اختصاص تنظیمات شبکه مانند IP به Clientها ✓
    • C) ذخیره فایل‌ها
    • D) Authentication کاربران

    پاسخ صحیح: B

    🧪 سؤال ۵ — Troubleshooting

    Client می‌تواند به IP یک Server دسترسی داشته باشد، اما با نام Server نمی‌تواند آن را پیدا کند. کدام سرویس باید یکی از اولین موارد بررسی باشد؟

    • A) RAID
    • B) DNS ✓
    • C) DHCP فقط
    • D) Print Spooler

    پاسخ صحیح: B — مشکل می‌تواند مربوط به Name Resolution باشد.

    🧪 سؤال ۶ — سناریویی

    یک Administrator می‌گوید: «چون Server Core GUI ندارد، پس نمی‌تواند DNS یا Active Directory را اجرا کند.»

    کدام پاسخ درست است؟

    • A) درست است.
    • B) Server Core فقط File Server است.

    • D) Server Core فقط برای Backup است.

    پاسخ صحیح: C — نداشتن Desktop Experience به معنی ناتوانی در اجرای Server Role نیست.

    🧪 سؤال ۷ — سناریویی

    یک شرکت ۳۰ Client دارد و می‌خواهد:

    • IPها خودکار اختصاص داده شوند.
    • کاربران مرکزی مدیریت شوند.
    • نام Serverها قابل Resolution باشد.

    • D) فقط File Server

    پاسخ صحیح: B — DHCP برای IP Configuration، AD DS برای Identity/Domain و DNS برای Name Resolution استفاده می‌شود.

Windows Server Editions و نصب سیستم‌عامل

دوره جامع Windows Server & Active Directory · نسخه ۲۰۲۲/۲۰۲۵

معرفی نسخه‌های Windows Server

مایکروسافت برای پاسخ‌گویی به نیازهای مختلف سازمانی، چندین نسخه (Edition) از Windows Server را ارائه می‌دهد. انتخاب نسخه مناسب تأثیر مستقیم بر هزینه لایسنس، قابلیت‌های در دسترس و مقیاس‌پذیری زیرساخت دارد.

در این درسنامه با مهم‌ترین نسخه‌ها، تفاوت‌های کلیدی آن‌ها و سناریوهای پیشنهادی برای هر کدام آشنا می‌شوید. همچنین فرآیند نصب و پیکربندی اولیه را به‌صورت گام‌به‌گام بررسی خواهیم کرد.

مقایسه نسخه‌های اصلی

نسخه حداکثر هسته Hyper-V Storage Spaces Direct سناریوی پیشنهادی
Standard نامحدود* ۲ ماشین مجازی خیر محیط‌های کوچک و متوسط
Datacenter نامحدود نامحدود بله مراکز داده و مجازی‌سازی سنگین
Essentials ۱۰ هسته محدود خیر کسب‌وکارهای کوچک (تا ۲۵ کاربر)
💡 نکته

لایسنس Windows Server بر اساس تعداد هسته‌های فیزیکی محاسبه می‌شود. حداقل لایسنس برای هر سرور ۱۶ هسته است؛ حتی اگر پردازنده تعداد کمتری داشته باشد.

نصب از طریق PowerShell (Server Core)

در محیط Server Core می‌توانید نقش‌ها و ویژگی‌ها را با دستور زیر نصب کنید:

PowerShell Install-WindowsFeature 
# نصب نقش Active Directory Domain Services
Install-WindowsFeature AD-Domain-Services -IncludeManagementTools

# نصب DNS Server
Install-WindowsFeature DNS -IncludeManagementTools

# بررسی وضعیت نصب
Get-WindowsFeature | Where-Object {$_.InstallState -eq "Installed"}
⚠️ هشدار

قبل از ارتقا (Upgrade) از نسخه‌های قدیمی‌تر، حتماً از اطلاعات مهم بک‌آپ بگیرید. برخی از نقش‌ها و ویژگی‌ها ممکن است در نسخه جدید پشتیبانی نشوند یا نیاز به پیکربندی مجدد داشته باشند.

📌 مثال عملی

فرض کنید یک سازمان با ۵۰ کاربر و ۳ سرور فیزیکی دارید. اگر قصد مجازی‌سازی بیش از ۲ ماشین مجازی روی هر سرور را دارید، نسخه Datacenter مقرون‌به‌صرفه‌تر خواهد بود؛ چون لایسنس نامحدود برای ماشین‌های مجازی ارائه می‌دهد.

Windows Server Core

Server Core نسخه‌ای بدون رابط گرافیکی (GUI) است که سطح حمله را کاهش می‌دهد و مصرف منابع را به حداقل می‌رساند. مدیریت این نسخه عمدتاً از طریق PowerShell، Windows Admin Center یا ابزارهای Remote انجام می‌شود.

  • مصرف RAM و Disk بسیار کمتر نسبت به Desktop Experience
  • به‌روزرسانی‌های کمتر و زمان راه‌اندازی سریع‌تر
  • امنیت بالاتر به‌دلیل کاهش سطح حمله
  • مناسب برای نقش‌هایی مثل DNS، DHCP، Hyper-V و Active Directory
🧪 تست خودآزمایی

سؤال: کدام نسخه از Windows Server برای محیط‌هایی با تعداد زیاد ماشین مجازی و نیاز به Storage Spaces Direct توصیه می‌شود؟

  • الف) Windows Server Standard
  • ب) Windows Server Essentials
  • ج) Windows Server Datacenter
  • د) Windows Server Foundation

پاسخ صحیح: گزینه ج — نسخه Datacenter امکانات کامل مجازی‌سازی و Storage Spaces Direct را فراهم می‌کند.
